# Tools: list / grep / read other panes

## Plan

- New module `crates/codon-agent/src/tools/pane_xref.rs`.
- `list_panes()` walks the active window's `Member` tree (Zed's
  `Pane`s + nested splits) and the per-pane `Item`s. For each item
  that has a `PaneInspect` impl, emit `{ pane_id, kind, label,
  summary }` where `pane_id` is a stable opaque ID generated by
  `PaneInspectRegistry`. Items without a `PaneInspect` impl are
  omitted.
- `grep_pane { pane_id, pattern, max_hits? }` resolves the pane_id
  to an entity through `PaneInspectRegistry`, then calls
  `PaneInspect::search` exactly like the current-pane variant.
  Returns `pane_unknown` for an unregistered id and `pane_other_
  window` for an id that belongs to a different window/workspace.
- `read_pane { pane_id, scrollback?, offset? }` mirrors
  `read_current_pane` against the resolved entity.
- Pane IDs are workspace-scoped: the registry's keys include the
  workspace's fingerprint (same fingerprint as
  `REQ:codon/agent-shared-memory#c-fingerprint` so the two are
  comparable). Cross-workspace lookups are rejected even if the
  user's session has both open.

## Acceptance

- `list_panes` from a window containing a terminal split + an
  editor + an FM returns three entries in left-to-right pane order.
- Calling `read_pane` with the editor's pane_id from the terminal
  pane succeeds (cross-pane within the same window).
- A pane_id from a different window returns `pane_other_window`.
- A pane_id from a different workspace returns
  `pane_other_workspace`.
- `cargo test -p codon-agent` passes.
