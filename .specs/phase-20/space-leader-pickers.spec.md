# Space-leader picker flow

## Plan

Today's `space` chords live only in the Helix editor mirror block
(`crates/codon-keymap/src/keymap.rs` under
`[bindings.editor.normal]`):

```toml
"space f"        = "file_finder::Toggle"
"space b"        = "..."   # (no tab_switcher in helix mirror today)
"space s"        = "outline::Toggle"
"space shift-s"  = "project_symbols::Toggle"
"space d"        = "editor::GoToDiagnostic"   # (not the picker)
"space r"        = "editor::Rename"
"space a"        = "editor::ToggleCodeActions"
# ...
```

The codon-keymap loader compiles `[bindings.editor.normal]` under a
`vim_mode == normal | helix_normal | helix_select` predicate, so
these chords don't fire when a terminal / fm / git-panel pane is
focused.

The phase-20 `c-leader-pickers` clause requires the picker chords to
fire *anywhere* a Normal mode is active. Implementation:

### Loader extension

Extend `KeymapBindings` in
[`crates/codon-keymap/src/keymap.rs`](spec:src:crates/codon-keymap/src/keymap.rs)
with a `global: Option<ModeBindings>` field (in addition to the
existing `global: HashMap<String, String>` un-scoped field — pick a
distinct field name like `global_normal` / `global_insert` to avoid
collision). Bindings under `[bindings.global.normal]` MUST compile
to the union predicate:

```
  (Editor && (vim_mode == normal || vim_mode == helix_normal || vim_mode == helix_select))
|| (Terminal     && pane_mode == normal)
|| (FileManager  && pane_mode == normal)
|| (GitPanel     && pane_mode == normal)
|| (AgentPanel   && pane_mode == normal)
|| (OutlinePanel && pane_mode == normal)
|| (DebugPanel   && pane_mode == normal)
```

The full list is generated by enumerating every pane kind that
publishes a `pane_mode` predicate today plus the editor's special
vim_mode predicate. Centralise the predicate string in a single
helper so the picker chords don't drift from the rest of the
`global.normal` surface.

Insert mode (`[bindings.global.insert]`) is symmetric but is not
needed for the picker flow — leave it as a future extension point.

### Embedded picker chords

Under the new `[bindings.global.normal]` add:

```toml
"space f"       = "file_finder::Toggle"
"space b"       = "tab_switcher::Toggle"
"space s"       = "outline::Toggle"
"space shift-s" = "project_symbols::Toggle"
"space d"       = "diagnostics::Deploy"
"space r"       = "projects::OpenRecent"
"space g"       = "codon_pickers::ChangedFilesPicker"
"space j"       = "codon_pickers::JumplistPicker"
"space '"       = "codon_pickers::LastPicker"
```

### Helix-mirror reconciliation

The Helix editor `[bindings.editor.normal]` block already binds
`space f` / `space s` / `space shift-s` / `space r` to different
actions (`editor::Rename`, etc.). For the picker letters that
collide:

- `space f` — global = `file_finder::Toggle`. Editor's Helix
  mirror has no `space f` today (Zed binds it to file finder).
  Keep convergent.
- `space s` — global = `outline::Toggle`. Editor's mirror has
  `space s = outline::Toggle`. Convergent.
- `space shift-s` — global = `project_symbols::Toggle`. Editor
  mirror same. Convergent.
- `space d` — global = `diagnostics::Deploy` (the picker). Editor
  mirror has `space d = editor::GoToDiagnostic` (the next-diag
  motion). **Conflict.** Resolve: the global flow wins
  (`diagnostics::Deploy` is the discoverable picker for "open
  diagnostics view"); the editor mirror MUST drop its `space d`
  binding and the Helix-cheatsheet path to GoToDiagnostic moves
  to a different chord (TBD at implementation — likely `]d` /
  `[d` for next/prev). Document the rebind in the merge commit.
- `space r` — global = `projects::OpenRecent`. Editor mirror has
  `space r = editor::Rename`. **Conflict.** The discoverable
  picker for "recent projects" is more cross-pane-valuable than
  symbol rename, which already lives on the LSP-rename code path.
  Move `editor::Rename` to a different chord in the editor block
  (proposal: `space shift-r`). Confirm with user before merging.
- `space a` — editor mirror only (`ToggleCodeActions`). Not in
  global flow. Leave as-is.

### Removal sequencing

This task lands together with
[TASK:phase-20/keymap-chord-rename](spec:TASK:phase-20/keymap-chord-rename)
— the rename task removes `prefix p X` and this task adds the
`space X` replacements. The two should land in one commit so no
intermediate state leaves pickers unreachable.
